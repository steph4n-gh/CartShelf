# Report a security problem

Report ordinary bugs through the project's issue tracker. Do not open a public issue containing a working exploit against the disk writer, credentials, private game data, or personal paths.

Use the repository hosting provider's private vulnerability-reporting channel when it is enabled. If no private channel is available, request a private reporting contact without posting exploit details. This source candidate does not establish a monitored security email address.

Include the affected version, platform, minimal reproduction, expected boundary, and observed impact. Use synthetic files and disposable media. Do not send ROMs, saves, complete card images, credentials, or an unredacted library catalog.

The most important boundaries are removable-disk admission, reviewed-plan binding, backup verification before erase, exact-build save matching, archive containment, immutable history, trusted bundled code, and separation of public source from user data.
